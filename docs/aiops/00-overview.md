# AIOps Kernel

> 基于 PentAGI 的 L1/L2 内核，构建面向 IT 运维与云自治运维的 agent 系统。

## 1. 这是什么

一个可持久化、角色参数化的 agent 内核，用来处理"告警 → 取证 → 诊断 → 建议 → （受控）执行 → 复盘"这条链路。

它不是一个聊天机器人，也不是一个告警聚合工具。它解决的问题是：**当线上出事时，把分散在日志、指标、变更记录、拓扑里的信息自动收拢成一条有时间线、有证据链的结论。**

## 3. 三层映射

| 层 | 在上游叫什么 | 在这里叫什么 | 是否改动 |
|---|---|---|---|
| L3 领域模型 | 渗透测试 SOP | 运维排障 SOP | **全部重写** |
| L2 控制平面 | flow / task / subtask 状态机 | 事故单 / 诊断阶段 / 取证步骤 | 小改 |
| L1 Harness | performer / tool / chain | 同左 | 复用 |
| L0 模型 | provider | 同左 | 复用 |

## 4. 阶段

| 阶段 | 范围 | 是否执行写操作 |
|---|---|---|
| **M0** | 只读诊断：单场景（K8s Pod CrashLoop），产出带证据的根因 | 否 |
| M1 | 三路取证（日志 / 指标 / 变更）+ 报告 + 告警接入 | 否 |
| M2 | Runbook 受控执行（人工审批 + 动作账本 + 回滚） | 是，低风险动作 |
| M3 | 自治闭环（SLO 内自动缓解） | 是，需一键回滚 |

**M0 的定位是验证，不是产品。** 它要回答三个问题：根因能不能找对、成本能不能接受、延迟够不够快。

## 5. 目录与语言约定

- **代码与注释**：英文（沿用上游 Go 风格）
- **提示词**（`*.tmpl`）：**中文**。除固定的学术与技术名词（如 incident commander、PromQL、OOMKilled、blast radius）保留英文外，正文一律中文
- **面向模型的展示文本**：**中文**。包括工具描述、`jsonschema_description`、参数校验的报错信息、回给模型的错误提示——凡是模型会读到的文字，都用中文
- **面向人的界面文案**：中文
- **设计文档**：中文，放在 `docs/aiops/`
- **标识符**：英文。工具名、字段名、角色名、日志里的键名保持英文，因为它们是程序和 schema 的一部分
- 新增提示词：`backend/pkg/templates/prompts/aiops/`
- 新增工具：`backend/pkg/tools/aiops/`

判据只有一条：**读这段文字的是模型还是人？** 两者都用中文；只有机器解析的部分（字段名、工具名、枚举值）保持英文。

## 6. M0 明确不做的事

- 不执行任何写操作（重启、扩容、回滚、改配置）
- 不改造沙箱（终端工具仍走 Docker，但 M0 的诊断不需要它）
- 不做多租户隔离与凭据管理（M2 再做）
- 不美化前端（先用现有页面，换术语即可）
- 不做告警聚合与降噪
